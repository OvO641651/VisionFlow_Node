## 一、项目是什么

**VisionFlowNode**（工程目录 `E:\opencv_python_3_8\PySide\VisionFlowNoed`，名字里少一个 `d`）是一个**节点式机器视觉软件**：
用户在画布上把功能方框连成一条数据流（采集 → 处理 → 检测 → 输出），软件按拓扑顺序执行，并把结果显示/保存下来。
布局与交互刻意对标**海康 VisionMaster**。

> **目标原话（用户）**："我想要做的是像海康 vision master 软件一样的数据流引擎。"
> **"影响必须由算子声明"（用户定稿的引擎语义）**：节点之间的影响只有两条正规通道 —— **声明的图像源绑定** 与 **ROI 继承**；
> **"数据流可视化 → 半自动跟随 → 带角度位置修正"** 是后续要走的演进路线（见第九节）。

## 三、架构总览

### 3.1 分层

```
界面层   main.ui / SetCameraID.ui（留工程根） + ui\（LineParamsDialog.ui 随窗口同目录）
         main.py(MainWindow) ── widgets\FlowPages(多页签) ── widgets\FlowChart(画布/节点/连线)
                              ── widgets\ImageGraphicsView(显示) ── widgets\ImageGalleryWidget(图库+工具栏)
                              ── 参数窗口：ui\GenericProcessDialog / LineParamsDialog / Circle / Gray
引擎层   core\flow_engine.py（拓扑排序 · 图像源绑定 · ROI 继承 · 节点执行 · 渲染层合成 · 结果缓存 · 显示键）
         core\param_store.py（参数归档）· core\project_store.py（方案读写）· core\commands.py（撤销/重做的命令与栈）· core\result_cache.py（结果缓存两池 LRU）
服务层   services\（碰 Qt 与硬件）：camera_service · video_service · gallery_service · undo_service（撤销 / 重做，**第 7 个 Mixin**）
契约层   core\NodeRegistry.py：NodeSpec（name/kind/run/draw/format_result/whole_image_param/param_specs）
         core\host_contract.py：6+1 个 Mixin 共享的**宿主契约**（65 个名字，`if TYPE_CHECKING:` 里声明，**运行时是空类**）
算子层   ops\process\ 6 个 · ops\color\ 1 个 · ops\source\ 3 个 · ops\sink\ 1 个 · ops\detect\ 3 个（直线识别 / 圆识别 / 人脸识别）   ← **一个节点一个文件**
公共层   core\ParamRules.py(参数校验规则表) · core\ImageIO.py(图片读写：支持中文路径) · core\ImageOps.py(ROI 等通用图像操作)
算法层   core\Detector.py：直线 / 圆（Hough）
```

### 3.2 节点契约（`NodeSpec`）与四类 kind

| kind | 含义 | 改数据层图像？ | 现有算子 |
|---|---|---|---|
| `process` | 处理：图像被改写，下游看得见 | ✅ | 灰度、取反、滤波、二值化、形态学、边缘提取、**颜色提取** |
| `detect` | 检测：图像原样透传，只产出结果数据 | ❌ | 直线识别、圆识别、**人脸识别** |
| `source` | 流程起点：自己造图 | ✅（是"新图"） | 图片源、视频源、相机源 |
| `sink` | 输出：图像原样透传，把结果写到外部（磁盘） | ❌ | 输出图像 |

两个派生属性是全工程的关键判据：
- **`modifies_image`** = `kind in (process, source)`：多上游"自动挑图像源"时，用它挑**真正改图**的那一支（否则中间的 sink 会冒充"最后一个改图节点"）。
- **`is_flow_level`** = `kind in (source, sink)`：这类节点的参数是**流程级配置**，**不按图片归档**（否则换图会把输出目录/文件名/视频路径清空）。

### 3.3 加一个算子需要动什么（这就是这套架构的价值）

1. **新建一个节点文件**（2026.10.12 起"**一个节点一个文件**"，见 5 节末与 §十 的目录重构），写一个算法方法（处理类）或 `run(detector, img, roi, params)`（其它类）；
2. 在同一文件里写 `*_SPECS` 声明（**参数表就是界面**——`GenericProcessDialog` 会照着自动生成"运行参数"页；`param_specs` 里还能声明 `visible_when` 行联动 / `slider_int` 进度条 / `per_node` 节点级参数）；
3. 在 `NodeRegistry.py` 末尾的分类注册里被自动收编；需要的话在 `main.py` 的树里加一项（`main.ui`）；
4. **如果这个算子有参数规则**（范围 / 奇偶 / 上下限互换这类），在 `ParamRules.py` 的规则表里登记一条 —— 窗口层与引擎层会各跑一遍同一张表。

**不用写界面、不用改引擎**（除非引入新的参数控件类型或新的执行语义）。

## 四、核心机制（含"为什么这么设计"）

### 4.1 数据层与渲染层分离（引擎的第一原则）

- **数据层**：`run()` 产出的图像 + 结果数据，在节点之间传递；
- **渲染层**：`draw()` 把结果画到**显示图的副本**上，供人看。

**为什么**：检测类算子的库函数（`cv2.HoughLinesP` 的绘制版）习惯"就地画线"，一旦画在数据层上，下游就会"看见绿线"——
那是**显示用的涂鸦**，不是图像内容。所以：检测类 `run()` 一律 `return img`（同一个对象）、`draw()` 只画显示层；
`NodeRegistry._run_line/_run_circle` 给算法的是 **ROI 的 `.copy()`**（把库函数的副作用丢在副本上）。

**副作用（2026.10.7 实测踩到）**：正因为检测结果只在渲染层，"输出图像"如果只存数据层，**文件里就没有任何检测内容** ⇒
于是有了 `save_content = 数据层图像 / 带检测叠加`（见 4.9）。

### 4.2 影响只能靠"声明的通道"

节点之间的影响**只有两条**：
1. **图像源绑定**（`input_source`）：自动 / 指定上游节点 / 全局图像源 —— 决定"这个节点从哪份图开始算"；
2. **ROI 继承**（`roi_inherit` + `roi_source` + `roi_margin`）：决定"处理哪一块"。

**为什么**：避免"隐式全局状态"式的耦合（否则任何算子都可能悄悄影响别的算子）。好处是可预测、可序列化（方案文件只存这两条通道就够）。

### 4.3 执行语义

| 语义 | 定义 |
|---|---|
| **执行顺序** | 按连线做 **拓扑排序**（Kahn）；孤立节点/环内节点**不执行**，日志如实提示 |
| **连续执行** | **只跑"当前选中节点 + 它的全部上游"**（`stop_at` 由入口显式传入，先经 `_upstream_closure()` 收窄；**与选中节点无关的并列分支不执行**，未执行的节点会在日志里列出来） |
| **单步执行** | **只执行选中的那一个节点**；输入 = 沿图像源绑定追到起点的那张图 |
| **执行范围** | 图库工具栏下拉框：`运行全部`（对每张图都跑一遍）/ `运行选中`（只跑当前图） |
| **取图来源（批次5 目标5-M2，2026.10.16）** | 流程里**有视频源 / 相机源节点** ⇒ "连续执行"**不展开成"跑图库每张"**（判据 `_uses_live_source()`）：走 `run_flow_continuous()`，由 `_flow_source_frame()` 按"主窗口当前图 → 起点节点"取图，取不到就**如实提示**；只有**纯静态图流程**才按"运行全部"逐张跑图库。删掉视频之后这条流程**仍算活源流程**（不会偷偷改用图库里的图片） |
| **停止** | 急停批量执行 + 停自动播放 + **收尾正在录制的视频** |

**为什么"连续执行要和画面一致"**（用户 2026.10.7 拍板，2026.10.8 目标5-M1 定稿）：画面本来就是"点哪个节点就显示执行到那个节点为止"的结果，如果执行还跑到底，就会出现"我选中的是前面的二值化，结果末尾的输出节点偷偷存了文件"。
★ **口径演进（务必按现行版理解）**：
- 2026.10.7 曾定为"按拓扑序执行到当前选中节点为止（前缀）"；
- **2026.10.8 目标5-M1 改成"选中节点 + 它的全部上游"（上游闭包）** —— 这样"两条并列链、选中右链末节点"时**左链完全不会执行**（前缀口径却会把左链一起跑掉）；
- 附带效果：不会再有"无关分支里偷偷存文件"，日志会给一行"连续执行：只跑「X」和它的上游；以下节点本次未执行：…"。

### 4.4 ROI 继承

`_resolve_roi()` 的优先级：
1. 勾了"继承上游" → `继承自=上游ROI框` 用上游**实际用的框**；`=上游结果框` 用上游**结果的外接框**（`result_bbox()`）；
2. 首选拿不到就自动换另一种（并在日志里说明）；
3. 都没有 → 用本节点自己画的 ROI；
4. 最后统一 **外扩 `roi_margin`** 并裁进图像范围。

日志会写 `← 继承上游ROI框` / `← 继承上游结果框` / `← 继承未生效（改用本节点 ROI）`——**让"继承到没继承到"看得见**。

### 4.5 参数归档：按图片，但"流程级节点"除外

- 每个节点的参数在内存里**按"图片标识"存多份**（切图时存档 + 载入）⇒ 一套流程可套用多张图，各图参数独立；
- **例外一（整节点级）**：`is_flow_level`（起点节点 + 输出节点）**不归档**。判据写在契约里，引擎和参数窗口都读它；
- **例外二（单参数级，2026.10.12 加）**：`param_specs` 里声明 **`"per_node": True`** 的参数**不按图归档** —— 它属于"这个节点用哪个模型 / 模板文件"这类配置。`NodeRegistry.node_level_param_keys(spec)` 读它；`_save_node_params()` 把它剔出图片槽、`_load_node_params()` 在 `params.clear()` 前留一份、载入后放回去。**现有唯一用例 = 人脸的 `cascade_file`**（级联文件换图不再重置）。
★ 这条坑已经踩过三次（图片源路径 / 输出目录 / 人脸级联文件）⇒ 以后加参数先问一句"**它跟当前这张图有关系吗**"。
- ⚠️ 实现细节坑：`_load_node_params()` 是**先 `params.clear()` 再载入**，所以流程级节点**必须跳过**，否则换一次图就把输出目录清空。

### 4.6 三种"键"（最容易被搞混的地方）

| 键 | 组成 | 用途 |
|---|---|---|
| **图片标识** `_image_key_of` | 文件路径（跨会话稳定）；视频帧 = `路径#帧号`；无路径才退化成 `id(对象)` | 参数存档 / 结果缓存 / 缩放记录 |
| **结果缓存键** | （图片标识, 页面 key, 执行方式） | 单步与连续分开、按页分开；只在内存；**相机帧不写缓存** |
| **画面键** | 普通图 = 文件路径；视频 = `video:路径`（**整段共用**）；相机 = `camera:编号` | 缩放/平移状态。视频整段共用是必须的：否则每帧都当成新图、缩放复位，播放时画面"一跳一跳" |

★ **结果缓存有上限（批次5 目标4，2026.10.15）**：`core\result_cache.py` 按**两池**管 —— **静态图 400 条 / 256 MB**、
**视频序列 120 条 / 64 MB**（序列池的键含 `#`，即 `路径#帧号`）；**命中即 `touch()` 移到最新 = 真 LRU**（不是 FIFO 近似）、
**写入即 `evict()`**。相机帧**不入缓存**（无界流）。
★ **活源轮的结果记在"视频帧键"下**（批次5 目标5-M2，2026.10.16）：`_execute_static()` 发现这一轮真用到视频源时，
把写缓存的键从"启动那一帧（静态图）"换成 `视频路径#帧号` —— 否则"切走再切回那张静态图"会看到视频帧的结果。

### 4.7 方案持久化（`.vfproj`）

- JSON / UTF-8 / 缩进 2；结构：`format / version / saved_at / current_page / last_source / pages[]`；
- **一个文件装一页**（用户口径）；"导入项目"把文件里的页**追加**到现有页后面（现有页一律保留）；
- **内容指纹去重**：`_page_fingerprint`（工作区）与 `_model_page_fingerprint`（文件模型）**结构必须完全一致**，指纹相同的页跳过（所以两个函数是刻意重复实现的）；
- **先解析 + 校验、全部通过才碰界面**：坏文件不会把界面搞成半成品（失败返回 False，界面保持原样）；
- 节点字段：`id / name / x / y / input_source / params / params_by_image`（漏了最后一个就会"存了读不回来"）。

### 4.8 图像源与图库

- **两类来源并存**：图库（主窗口当前图 + 列表）与**起点节点**（图片源/视频源/相机源）；
- `_flow_source_frame()`：主窗口当前图优先，其次问起点节点，都没有才提示"请先导入图片/视频"；
- 图片源节点与图库**双向同步**：点缩略图 → 同步"图片源"节点路径；删图库条目 → 清相关节点路径（并记进 `_removed_paths`，防止又被自动加回来）。
- **"补图库"（把图片源节点指定的图加进图库）只在静态图轮做**（批次5 目标5-M2，2026.10.16）：活源（视频 / 相机）轮不补 ——
  否则空图库时会突然多出一张"图片源"的图，看起来像"相机第一帧被塞进图库"（实测探针定过案）。
- **图库缩略图是固定尺寸**（批次5 目标5-M1，2026.10.16）：统一装进**固定 80×60 画布**（等比缩放 + 居中 + 浅灰留白），
  单元格由 `setGridSize()` 钉死。**不能让它随原图长宽比变**——列表开着 `setUniformItemSizes(True)`，一项变窄会把**整列表**的单元格压窄。
- **"图像源 (n/N)"标签按"谁在播"归属**（批次5 目标5-M1/M2）：视频 / 相机出画面期间归播放侧（`set_count_locked()`），
  播放中点图库只改选中项、不抢标签；活源轮显示"视频帧 (n/总数)"（相机轮显示"相机画面"）。

### 4.9 输出节点（批次4 目标3-M5）

- **参数**：输出目录（**必须每次手填**）/ 输出文件名（默认 = 输入图片名）/ **输出类型**（自动·图片序列·视频文件）/ 图片格式 / 视频格式 / 视频帧率 / **保存内容**（数据层图像·**带检测叠加**）/ 重名策略（**自动编号**）；
- **"自动"档**：图片源 ⇒ 图片序列；视频源/相机源 ⇒ **视频文件**（用户口径："输入是视频就存视频、是摄像头就存视频"）；
- **"带检测叠加"怎么来的**：检测类不改数据层 ⇒ 主窗口在执行到输出节点那一刻，用 `_render_display(in_img, executed, draw_roi=False)`
  把**已执行节点的检测结果**画好（**不画 ROI 辅助框**），经 `OVERLAY_PROVIDER` 交给节点；取不到就退回数据层。
  **默认选叠加**，因为纯处理链下两档**像素完全一样**（用例逐像素证过）⇒ 默认它不改变旧行为，却让检测内容能存下来；
- **录制生命周期**：第一帧自动开录（定尺寸/帧率）→ 每帧写一次 → **6 处收尾**（「停止」/ 播到末尾·关相机 / 换页 / 删节点 / 关程序 / 关换相机）；
  **尺寸或输出参数变化 ⇒ 收尾旧文件 + 另开新文件**；**0 帧 ⇒ 删掉空文件**；
- **视频格式**：实测本机 `mp4v / XVID / MJPG` 都能写能读；**不做 H.264**（依赖本机没有的 openh264 dll，会打印加载失败，靠回退侥幸能写）。
  体积实测（1280×720 / 25fps）：mp4v ≈ 7.7 MB/分钟、XVID ≈ 7.9、MJPG ≈ 23；
- **帧率口径**：手填 > 来源（视频源读到的 / 相机兜 30）> 25，按"**每写一帧算一帧**"；
- **失败一律不弹窗**（目录为空 / 写不进去 / 编码器不支持），只写执行日志。

### 4.10 设备与播放

- **相机**：主窗口统一开关（`_open_camera_device` / `_release_camera_device`），相机源节点通过注入的取帧器**复用**；
  **一轮执行只读一次相机**（否则"画面"和"算法算的那张"不是同一帧）；`「停止」= 暂停、`删除` = 关相机`（用户拍板）。
- **视频**：`VideoSourceOps.py` 各自缓存 `VideoCapture`（按 `(路径, mtime, 大小)`），与主窗口播放**各读各的、不抢读指针**；
  `run_video()` **只读当前帧、不前进**，前进由主窗口 `_advance_video_cursor()` 统一做（同一轮多节点共用同一帧）。
- **自动出画面**：视频与相机**共用同一个 QTimer**；视频间隔 = `1000/fps`（坏值兜 25，夹到 5~1000ms），相机按 30ms。
- **帧游标到末尾（批次5 目标5-M2，2026.10.16）**：`_advance_video_cursor()` 在**单步那条路**处理末尾 —— 勾了「到末尾回到开头」⇒
  **回卷到 0**；没勾 ⇒ **停在最后一帧**（不再一直涨过总帧数、画面却卡在第一帧）。**播放那条路**由 `_video_tick` 自己管末尾（行为不变）。
- **"图像源 (n/N)"标签的归属**：视频 / 相机出画面期间**归播放侧**（`set_count_locked()`），
  活源轮显示 **"视频帧 (n/总数)"**（总数按 `video_info()` 读）、相机轮显示 **"相机画面"**；静态图轮才显示"图像源 (n/N)"。
- **"画布上当前是不是活源帧"**：引擎记一个 `_canvas_shows_live` 标记（这一轮真用到视频 / 相机 ⇒ True）——
  删除按钮、日志标签、结果缓存键三处都以它 / 图片标识为准，别再看 `current_static_image` 猜。

### 4.11 参数校验与内联提示（批次4 目标4，决策 d = C 改造版）

- **规则表**：`ParamRules.py`；**唯一入口** `run_validation(spec, params) -> (fixed, corrections, errors)`；
- **同一张表跑两遍**：
  - **参数窗口出口**：能纠正 ⇒ **黄字**提示"已自动纠正…"并写回控件；纠正不了 ⇒ **红字**提示（**绝不弹窗**）；
  - **引擎出口**：`_execute_node()` 前跑一遍 ⇒ 日志尾部写 `← 已自动纠正：…`；纠正不了的 ⇒ **跳过该节点**、
    写一行"参数非法（…），已跳过本节点"，图像**原样透传**给下游；
- **数值输入是"软范围"**：控件自身范围被放宽（真范围存在动态属性 `_soft_min` / `_soft_max`），
  可以先把越界值打完，回车 / 失焦 / 点执行时才夹回 ⇒ 断言"界面调不到某值"要看 `_soft_min` / `_soft_max`；
- 实测结论（写规则前先实测库行为）：Canny 低>高**不崩**（OpenCV 自己交换）、圆 `param1/param2 = 0` **抛异常**
  且界面可达（唯一"界面可达且会崩"的真 bug）、核大小偶数抛异常但既有 `_odd()` 已兜住。

### 4.12 通用错误通道（日志红字，批次4 目标5-M2）

用户要求："在日志中使用红色字体写明出错的原因"。实现：

- 算子在结果 dict 里带 **`{"__error__": True}`** ⇒ `main.py::_format_result_text()` 在文案前加内部标记
  `LOG_ERROR_MARK`（`\u26a0`）⇒ `_update_execution_log()` 见到标记就把**那一行整行涂红**（`#c80000`），
  并把标记从显示文本里去掉；
- **为什么用"文案前缀标记"而不给 `exec_info` 元组加第 6 项**：元组的形状被结果缓存、日志刷新、一堆老断言共用，
  加一项回归面太大；
- 现有落点：**人脸识别**（未选级联文件 / 文件不存在 / 不是有效级联文件）+ **输出图像** 5 处"保存失败"。
  **通道是通用的** —— 以后"模块未实现""参数非法已跳过"想标红，加一个 `__error__` 即可。
- **日志表格按像素滚动**（批次5 目标5-M2，2026.10.16）：`setVerticalScrollMode / setHorizontalScrollMode(ScrollPerPixel)`
  —— 默认的 `ScrollPerItem` 是"一滚一行"，用户实测反馈"滚动条不能连续滚动"。
- **日志会自动滚到底**（批次5 目标4，2026.10.15）：写入与追加提示行之后都 `scrollToBottom()`
  —— 之前"日志看不见最新一行"的真症结就是**全工程没有自动滚动**，不是日志太长。

### 4.13 参数窗口的两项通用能力（批次4 目标5-M2）

都是**通用能力**（不只服务那两个识别节点）：

- **`visible_when`（行联动）**：`param_specs` 的 options 写 `"visible_when": (依赖键, [允许的值…])`，
  只有依赖参数取到这些值时那一行才显示（颜色提取选 HSV 就只显示 HSV 那 6 行）；
  实现 = 建行时记进 `_linked_rows` → `_bind_linked_rows()` 接信号 → `_apply_param_visibility()` 用 `setVisible` 显隐；
- **`slider_int`（进度条 + 微调框）**：界面 = `参数名 ──进度条── 数值`；`QSlider`（真范围）+
  `QSpinBox`（软范围）**双向联动**；**只给声明该类型的参数用**（颜色提取 12 个阈值），存量 `int` 参数界面零改动；
- 配套：`file` 控件的 **`plain: True`**（浏览时只选文件、**不导进图库**，给级联文件用）；
  combo 用 `AdjustToMinimumContentsLengthWithIcon` 可压窄（窄了显示省略号）；
- **布局规则（踩了两轮才定）**："运行参数"页整页包在 **`QScrollArea`** 里（**提示行出现不改变窗口大小**、
  参数行固定顶部）；**横向滚动条禁用** ⇒ 内容的**最小宽必须 ≤ 视口宽**，且**窗口不允许被缩到装不下内容**
  （`LineParamsDialog._sync_scroll_min_width()` 抬滚动区最小宽兜底）。

### 4.14 图片读写与中文路径（`ImageIO.py`）

- **问题**：Windows 上 `cv2.imread` / `cv2.imwrite` 走**窄字符（ANSI）文件 API**，**文件名 / 目录名带中文**就找不到文件，
  而且 `imread` 是**返回 None（不抛异常）** ⇒ 表现为"静默读不出来"（控制台只有一行 `cv::findDecoder … can't open/read file`）；
- **修法**：统一走字节流 —— 读 = `np.fromfile` + `cv2.imdecode`；写 = `cv2.imencode` + `buffer.tofile`；
  包成 `ImageIO.read_image / write_image`（**返回值契约与 cv2 一致**：失败返回 None / False，调用方一行不用改）；
- **四个入口**：`ImageSourceOps.py`（图片源读图）、`main.py`（导入图片进图库）、`ImageGalleryWidget.py`（缩略图）、
  `OutputOps.py`（**保存也一起修**：输出目录 / 文件名带中文时原来会判"保存失败"）；
- **视频不受影响**（`VideoCapture` / `VideoWriter` 走 FFmpeg，实测中文路径正常）。

### 4.15 结果缓存上限与 LRU（批次5 目标4，2026.10.15）

- **两池**（`core/result_cache.py`）：**静态图池 400 条 / 256 MB**、**视频序列池 120 条 / 64 MB**
  （序列池的键含 `#`，即 `路径#帧号`，由 `is_sequence_key()` 判定）；**相机帧不入缓存**（无界流）；
- **是真 LRU**：命中（切图 / 显示上次结果 / 批量收尾）时 `touch()` 把键移到最新；**写入后立刻 `evict()`**；
- **为什么要做**：改前那段"上限"**只写在视频分支里** ⇒ 静态图批量跑**根本没有上限**（实测 66 张就 62.4 MB，
  单条最大 5.72 MB ⇒ 同样 400 条最坏可到 2.3 GB），而且是 FIFO 近似（命中不刷新顺序）；
- **判据**：`tests\dsh_t5g4_cache_check.py`（条数 / 字节上限、**真 LRU 判别**、两池隔离、淘汰后重算逐像素一致、删图库项清缓存）。

### 4.16 撤销 / 重做（命令模式，批次5 目标4，2026.10.15）

- **命令零 Qt**（`core/commands.py`）：`AddNodeCommand` / `RemoveNodeCommand` / `AddEdgeCommand` / `RemoveEdgeCommand` /
  `SetParamsCommand` / `MoveNodeCommand` + `UndoStack`（**上限 50 步**；用回调通知、不引 Qt Signal）；
- ★ **命令只存 uid、不存对象引用**：`services/undo_service.py` 的 `_UndoContext` 持 **uid 注册表**，
  执行时 `resolve(uid)` 取"现在活着的那个" —— 撤销会销毁 Qt 对象、重做是**重建新对象**，存引用必然出现
  "线飘" / "按钮灰了节点还在"；`resolve()` 做**两层探活**（还在不在当前 `flow_nodes` 里 + C++ 对象是否已销毁），
  删除类命令**先把 uid 摘掉**（防解析到僵尸对象）；
- ★ **栈按页面各一条**（`_undo_stacks[页 key]`）：换页**只切换、不清空**（用户口径："切回来还要能撤销"）；
  导入 / 新建的页面**第一次用到时栈是空的** ⇒ "撤销最多只能撤到导入时"天然成立；
- ★ **要"带键"的状态**：参数按图片归档 ⇒ `SetParamsCommand` 记 `image_key`（撤销只改"那张图"的存档，别的图不动）；
- **记录点**：`main.py` 的四个改动入口（建 / 删节点、连 / 删连线）+ 参数窗口关闭 + **节点拖动**（400ms 去抖成一条命令）；
- **撤销 / 重做同步"未保存"标记**：撤到栈底 ⇒ `clear_dirty()`、重做 ⇒ 标脏（否则"全撤完关页面还提示有修改"）；
- **界面**：菜单「编辑」+ 顶部两个按钮（初始灰、按栈状态联动）；**快捷键暂不做**（用户口径：后续统一做）；
- **判据**：`tests\dsh_t5g4_undo_check.py`（往返、删节点连带连线、栈上限、每页独立、导入基准、参数按图恢复、拖动去抖、uid 身份连续）。

### 2.3 ★ 验收方式（用户已点选：甲）

**甲 = 改前 / 改后截图对照 + 新基线登记 + 功能用例一套不少**，落地办法：

1. **每个 M 动手前**先截"改前"图（`backups\_ui_preview\`），改完截"改后"图，**两张都记 sha256**，并**登记《截图索引》**；
2. **功能用例一套不少**：门禁 **44 套 1018 项**必须全绿（UI 改动最容易碰到 `dsh_m2_v5_check` / `dsh_width_check` / `dsh_t5g2_api_check` / `dsh_doc_consistency_check`）；
3. **行为不回归**：只准改"外观"，结果类断言（逐像素一致、缓存键、撤销语义…）继续有效；
4. **用户手工验收**：每个目标做完请用户看一眼（批次5 的老做法 = "用户点选 → 我落地 → 用户复测"）。

### 2.4 ★ UI 改动的三条硬约束（批次5 实测踩过，写在这里防回归）

1. **控件对象名尽量不动**：44 套门禁里**大量直读**运行时控件名，例如
   `w.btn_continuous` · `w.execution_log` · `w.gallery_widget` · `w.image_view` · `w.action_undo` · `w.btn_undo` …
   ⇒ **只改外观与布局最省事**；确实要改名的（例如**删掉「启动」「停止」两个按钮**），必须**先 grep 用例引用、同批同步改用例**，并在日志里写清改了哪些。
2. **`.ui` 只是"摆占位"，真源在运行时**：控件由 `QUiLoader` 载入 + `main.py` 里 `findChild` 收编
   ⇒ 删 / 挪 / 改名控件会让 `findChild` 返回 `None`（有兜底的地方会静默自建，反而更难发现）⇒ 改 `.ui` 后**要逐条核对 `findChild` 的调用点**。
3. **批次5 的"界面零变化"红线在批次6 作废**，换成 §2.3 的"**截图对照 + 新基线 + 用例全绿**"。

### 4.1 M1 ✅ 画布滚动条问题（**真 bug，2026.10.17 已落地**）

- **用户原话**："现在的画布的滚动条存在的问题：**节点向右移动到界限后会出现滚动条，但是其他节点会留在最左边（开始创建时是放在中间的）**。"
  用户补充口径（同日）："**能否将画布设置大一点，滚动条初始就显示出来，然后画布上显示的内容为整图的左上角部分**……"
- **实测根因**：`widgets/FlowChart.py` **从不设 `sceneRect`**（全工程只有图片视图 / ROI 窗口在用）⇒ 场景矩形由 Qt **按内容自动增长**；
  内容小于视口时视图**自动居中**、内容超出视口后视图**锚定场景矩形左上角** ⇒ 拖动节点时其余节点**整体跳到左边**。
- ★ **实际做法（方案 Z：固定大画布，已落地）**：
  1. `widgets/FlowChart.py` 新增模块常量 **`CANVAS_W, CANVAS_H = 4000, 3000`**、**`CANVAS_MARGIN = 200`**；
  2. `FlowchartView` 新增 **`_apply_canvas_rect(goto_topleft=False)`**：`base = QRectF(0, 0, 4000, 3000)`；
     若 `not base.contains(scene.itemsBoundingRect())` ⇒ `base = base.united(content.adjusted(0, 0, MARGIN, MARGIN))`
     （★ **原点恒 (0,0)、只向右下增长**）；`scene.setSceneRect(base)`；`goto_topleft=True` 时把两条滚动条的 `value` 拨到 `minimum()`；
  3. `FlowchartView.__init__` ⇒ `_apply_canvas_rect(goto_topleft=True)`（**每页建视图时**就定好：滚动条初始可见 + 停左上角），
     并置 `self._content_positioned = False`（这一页是否"跟过内容"）；
  4. 新增 **`goto_content_or_topleft()`**：有节点 ⇒ `centerOn(第一个节点)`（**导入方案 / 首次出现内容 ⇒ 跟到内容**），空页 ⇒ 左上角；
  5. **调用时机**：`FlowchartView.mouseReleaseEvent` 末尾（拖动释放后兜底重算）· `main.py::add_flow_node`（首次有内容 ⇒ 跟到内容，否则兜底重算）·
     `main.py::add_edge` / `delete_flow_node`（兜底重算，无副作用）；
  6. **起始点**：`main.py::_create_node_from_name` 与 `widgets/FlowChart.py::_on_tree_double_click` 两处的 `(20, 20)` 改成 **`(80, 80)`**；

  1. **中键（滚轮键）拖动画布**：把"左键平移"让给框选；★ Qt 的 `ScrollHandDrag` **只吃左键** ⇒ 中键平移必须**自己在视图层实现**（记起点 + 抓取光标 + 按位移改两条滚动条）；**左键在空白处不再平移**；
  2. **左键框选 + 多节点一起移动**：`RubberBandDrag` 负责框选（选中项进 `scene.selectedItems()`），"一起移动"要自己写 —— 拖动**任一被选中节点**时把**同一段位移**同时应用到所有选中节点；★ **撤销必须只记一条**（否则框选移动一次会刷出 N 条撤销记录，手感极差）；移动后 `update_all_edges()` 兜底刷新连线；
  3. **Ctrl+滚轮缩放**（顺带一起做）：`FlowchartView` 现在**没有任何缩放 / 滚轮逻辑**（全工程的 `wheelEvent/scale/setTransform` 只在图片视图与 ROI 窗口）⇒ 从零加、不会撞既有行为；缩放**只对视图设变换**（节点 / 连线 / 网格一起缩放）· **以鼠标位置为锚点** · 比例夹在 **0.2×~4×** · 用 `self._zoom` 集中管理（★ **不要 `scale()` 无限累乘**）。
- **与别处的关系**：M2 改节点形状时**顺手保证 `shape()` 正确**（框选命中用它）；M5 的吸附规则被本 M 复用；M3 小地图要跟随缩放同步视口矩形。
- **判据（草案 6 条）**：① 中键拖动 ⇒ 滚动条位移 = 鼠标位移（误差 ≤ 1px）；**左键空白拖动 ⇒ 滚动条不变**；② 框选 ⇒ `selectedItems()` = 框住 / 相交的节点集合；③ ★ 多节点移动 ⇒ 所有被选中节点位移一致（≤ 0.1px）；④ ★ **撤销一次全部回位**（栈深度 +1）；⑤ 移动后连线端点仍贴锚点（< 1.5px）；⑥ Ctrl+滚轮 ⇒ 一起缩放（`transform().m11()` 变化、节点**场景坐标不变**）、锚点 = 鼠标位置、比例被夹取。
- **落点**：`widgets/FlowChart.py`（`dragMode` / `mousePress-Move-Release` / `wheelEvent` + 多选拖动广播）· `widgets/FlowChart.py` 的 `NodeItem`（被选中时的位移广播）· 新建 `tests\dsh_t6_m7_check.py` · 帮助页（目标3-M2）里补一句"中键拖动画布 / 左键框选 / Ctrl+滚轮缩放"。
- ★ **待拍板 3 条（用户尚未答复）**：① 本 M 是否含 **Ctrl+滚轮缩放**（建议含 —— 同一个鼠标事件里一起做，省一次返工）；② 中键平移时要不要**抓取手型光标**（建议要，一眼能看出在平移）；③ 框选时**部分相交**的节点算不算选中（建议算，符合"快速移动一批"的意图）。
